# C1: Net foundation

What changed
- `server/relay.gd`: standalone headless Godot script (TCPServer + WebSocketPeer, no other game scripts). Rooms with a 6-character code
  (`ABCDEFGHJKLMNPQRSTUVWXYZ23456789`), max 4 players, host = id 1, joiners 2, 3, ... The first text message is the hello
  (`create` / `join`), replies are `created` / `joined` / `error`, then `peer_joined`, `peer_left`, `host_left`. Game packets are
  binary: `[target:int32][payload]` in, `[from:int32][payload]` out (0 = everybody else, > 0 = one player, < 0 = all except). Host leaves = room closed.
  Limits: 200 rooms, 600 connections, 10 s to say hello, names cleaned to 16 printable chars. Run: see CLAUDE.md. Options `--port=`, `--bind=`.
- `scripts/relay_peer.gd` (`RelayPeer`, `MultiplayerPeerExtension`): the client side, so normal `@rpc` works with the host as peer 1.
  Also `clean_code()` / `clean_name()` (unit tested).
- `scripts/net.gd`, autoload `Net`: `await Net.host(name) -> String` (code, "" on failure), `await Net.join(code, name) -> bool`,
  `leave()`, `is_online()`, `is_host()`, `my_id()`, `players` (id -> name), `player_name(id)`. Signals `room_created`, `joined`,
  `player_joined`, `player_left`, `failed(text)`, `host_left`. `failed` carries friendly text (`Net.REASONS`). `relay_url` defaults to
  `wss://slimeharvest.imogen.dev/relay`; `--relay=ws://127.0.0.1:PORT` overrides it.
- `server/*` added to the export exclude filters. Net is added to `project.godot` autoloads.
- Tests: `tests/net_test.tscn` (+ `net_test.gd`, `net_probe.gd`): the host process starts a relay and two joiner processes. Checks the raw
  protocol (create, join, full room, wrong/short code, bad hello, broadcast and direct packets, player left, host left, room gone), then a real
  `Net` run: host + 2 joiners, RPC round trip with arguments, a joiner leaving (`player_left`), the host leaving (`host_left` in the other
  process), failed join, bad code, unreachable relay. 40 checks. `run_tests.gd` got 8 checks for `clean_code`/`clean_name`.

Testing: `net_test.tscn` passes (run 3 times), unit tests 1223 checks 0 failed, aim test passes, playthrough defend saved the farm on day 13,
title and `main.tscn` smoke runs print only the known shutdown lines. Every process was killed afterwards. No screenshot: nothing visible yet (C2 adds the lobby).

Gotchas found
- A server that closes a WebSocket right after `send_text` can lose that message on the client. The relay sends errors and `host_left` and
  closes about 1 s later (`REFUSED_LINGER_MS`).
- A multiplayer peer must be connecting when it is assigned to `multiplayer`, so `Net` starts the connection first, then assigns it.
- `--script` tests can't compile anything that names `Net`, hence a scene test.
- Passing a typed array built with `+` to a function that wants `Array[String]` fails; the test helpers take plain `Array`.

Known limits
- Nothing in the game uses `Net` yet (C2/C3). Only localhost was tested; wss through nginx is for C4 and the VPS step.
- `_disconnect_peer` (kick) does nothing. No rate limit per player, only size limits (2 MB buffers, 1 MB packets); C3 snapshots must fit.
- Joiners see each other (all peers are announced to all), which RPC with `any_peer` would allow; C3 should send everything through the host.
- Not tested in a browser build.
