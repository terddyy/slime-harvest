# A3: Settings menu

What changed
- `scripts/settings.gd` (`Settings`, pure, tested): volumes (master/music/sfx 0-1), fullscreen, key bindings, `user://settings.cfg`
  (ConfigFile). Holds `DEFAULT_BINDINGS` (moved from `Game.KEY_BINDINGS`). Rebind rules: a key that another slot uses is swapped
  with it; Esc/Enter are reserved and `pause` can't be rebound; bad or clashing values in the file fall back to the defaults.
  `fill_keys()` fills `{action}` placeholders for How to Play.
- `scripts/settings_menu.gd` (`SettingsMenu`): sliders, fullscreen box (hidden on web), scrolling key list (click, press a key,
  Esc cancels), message line for swaps/refusals, Reset keys, Back. Saves on close. Opened from the title and the pause menu.
- `Game`: owns `settings`; `_ready` loads it before building the input map; `apply_key_bindings()` (rebuilds the actions) and
  `apply_display()` (fullscreen).
- `Audio`: creates `Music` and `SFX` buses in code (send to Master), players use them, `apply_settings()` sets bus volumes (0 = mute).
- How to Play shows the current keys. GDD controls table, CLAUDE.md layout updated.

Testing: unit tests 1066 checks (settings save/load, damaged file, swap, reserved keys, reset), aim test, title and main smoke
runs clean (only the known shutdown lines). A temp scene drove the capture flow with real key events (Esc cancels, F rebinds
interact). Screenshots of the title, settings and How to Play (with a rebound key) read at 960x540.

Known limits
- Tutorial and loading tips still name the default keys (E, Tab...) in their text.
- How to Play always writes "/ arrows" after the move keys, even if the arrow slots were rebound.
- Fullscreen and the web build were not checked on a real window / browser here.
