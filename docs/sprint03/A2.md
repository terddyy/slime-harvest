# A2: Loading screens

What changed
- Web: `html/shell.html` is the custom shell (`html/custom_html_shell` in the Web preset): logo, progress bar driven by
  `onProgress`, random tip, error message if the browser can't run it. Uses `getMissingFeatures({threads: $GODOT_THREADS_ENABLED})`
  so it works with thread support off. The tip list is a copy of `LoadingTips.TIPS`; keep both in sync.
- Desktop: boot splash = `assets/generated/logo.png` on the dark brown background (`boot_splash/*` in `project.godot`).
- In game: `Game.enter_farm()` (used by New Game, Continue, restart) goes to `scenes/loading.tscn`, `LoadingScreen` calls
  `ResourceLoader.load_threaded_request(MAIN_SCENE)`, shows bar + tip (min 0.4 s), then `change_scene_to_packed`.
  Load failure goes back to the title.
- `scripts/loading_tips.gd` (pure, tested in `tests/run_tests.gd`). `html/*` added to the export exclude filters.
- Docs: CLAUDE.md layout, ASSETS.md.

Testing: unit tests 1039 checks, 0 failed; aim test passes; title and main smoke runs clean (only the known
"resources still in use" shutdown line). Loading screenshot read (logo, bar, tip). Web export served with
`python -m http.server`: shell shows, game starts, no console errors. (The first run of the shell failed with
"Missing: Cross-Origin Isolation" until `getMissingFeatures` was given the threads flag; fixed.)

Known limits
- Twice, right after `--import`/export, a windowed run of loading.tscn printed many "Could not preload resource" parse
  errors from the threaded scene load; the game still loaded. Not reproducible in 10+ later runs. Watch for it.
- On a fast PC the in-game bar flashes by (0.4 s minimum). The desktop boot splash was not visually checked (no exe export run).
- The web shell logo is scaled with `image-rendering: pixelated` to 320 px wide.
